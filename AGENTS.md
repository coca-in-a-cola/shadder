# Инструкции проекта

## Общение

- Использовать skill `caveman`: отвечать кратко, по существу, без вводных фраз.
- Сохранять техническую точность, имена API, пути и команды. Код писать в обычном стиле.
- Отвечать на языке пользователя.

## Инструменты

- Команды терминала начинать с `rtk`, чтобы сокращать вывод и расход токенов.
- Использовать подходящую обёртку: `rtk git`, `rtk err`, `rtk test`. Для неподдерживаемых команд — `rtk proxy <команда>`.
- Для поиска, чтения и изменения файлов предпочитать специализированные инструменты; требование `rtk` относится к терминалу.
- Для изучения кода и перед изменением реализации сначала использовать MCP CodeGraph (`codegraph_explore`): запрашивать нужные символы, связи и затрагиваемые участки.
- Уже полученный через CodeGraph исходный код повторно не читать без причины. Обычные инструменты использовать для документации, конфигурации, недостающего контекста и устаревших результатов индекса.
- Если индекс CodeGraph отсутствует или сервис недоступен, использовать обычные инструменты. Самостоятельно индекс не создавать.

## Архитектура и реализация

- В неоднозначных технических ситуациях обращаться к исходникам Godot: готовые решения можно заимствовать и адаптировать к архитектуре проекта.
- В `examples/` менять минимум кода. Общую логику, загрузчики и управление ресурсами размещать во фреймворке.
- Примеры должны преимущественно описывать сцену и задавать параметры через простой API фреймворка.
- Для нетривиальных изменений сначала составлять план с учётом существующей архитектуры и зависимостей.
